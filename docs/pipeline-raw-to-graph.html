MOOCCube: từ raw data đến Knowledge Graph

Qui trình trong repo courserec (UPGPR): 4 file quan hệ TSV, lọc, đánh index, ghi file phẳng, chia train/val/test, rồi dựng KG dạng dict lồng nhau cho agent RL đi trên đồ thị.

Dữ liệu trên trang là toy data tự tạo, ID giả định (bộ MOOCCube thật không có trong repo, chưa verify format ID gốc). Logic lọc, đánh index, ghi file, dựng graph viết lại từ code thật (preprocess_mooc.py, make_dataset.py, data_utils.py, knowledge_graph.py). Kéo slider để thấy ngưỡng lọc tác động thế nào.

1. Raw data và lọc

preprocess_mooc.py: read_all_relations (dòng 15-31), get_enrolments (34-42)

Mỗi file là TSV 2 cột không header (đuôi .json nhưng đọc bằng read_csv(delimiter="\t")). Tên cột lấy từ tên file. Dòng bị gạch là dòng bị loại, kèm lý do.

Thứ tự lọc

  1. course-concept: đếm số course của mỗi concept trên bảng raw, giữ concept có đếm > min_concept_count (so sánh > chặt).
  2. user-course: chỉ giữ course có trong school-course.
  3. Trên kết quả bước 2, đếm enrolment mỗi user, giữ user có >= min_user_count (so sánh >=).
Hai ngưỡng dùng hai dấu so sánh khác nhau (> và >=). Đếm user diễn ra sau khi bỏ course không có school, nên user có thể rớt dù raw đủ enrolment.

2. Entity và đánh index

preprocess_mooc.py: get_all_entities (45-66), get_entity_to_idx (81-92), save_entities (75-78)

Mỗi loại entity là unique() theo thứ tự xuất hiện, ghi ra <entity>.txt, mỗi dòng 1 ID. Số dòng (từ 0) chính là index dùng ở mọi file sau.

  • users, courses lấy từ enrolment đã lọc. teachers, schools lấy từ các course còn lại, tên teacher đổi " " thành "_".
  • concepts lấy từ bảng course-concept đã lọc ở bước 1, không giới hạn theo course còn lại, nên có thể có concept chỉ gắn với course đã bị loại (nút concept đó sẽ không nối với course nào trong KG).

3. File phẳng thẳng hàng theo course

preprocess_mooc.py: save_enrolments (95-109), save_all_relations (116-167)

Ba file quan hệ có đúng 1 dòng mỗi course, cùng thứ tự với courses.txt. Dòng i của file quan hệ mô tả course thứ i. Course không có teacher/concept vẫn giữ 1 dòng rỗng để không lệch hàng. Rê chuột vào hàng để thấy tương ứng.

4. Split train/validation/test và nạp vào Dataset

make_dataset.py: split_train_test_data_by_user (34-62), Dataset(...) (data_utils.py)

Split theo từng user, không theo thời gian: mỗi user lấy 80% course làm train, phần còn lại chia đôi cho validation và test (ratio 0.8, ratio_validation 0.5). Ví dụ 1 user có 10 enrolment:

sklearn train_test_split, seed cố định ở bản thật (set_random_seed)
  • Ba file train.txt, validation.txt, test.txt: mỗi dòng user_idx course_idx.
  • Dataset(data_dir, KG_ARGS) dùng set_name="train" mặc định, nên KG chỉ chứa edge enroll của train. Test/validation không rò vào đồ thị.
  • Dataset load vocab từ entity_files và danh sách chỉ số từ item_relation trong config (mooc.json).

5. Dựng KnowledgeGraph

knowledge_graph.py: _load_entities, _load_enrolments, _load_knowledge, _add_edge, _clean

Cấu trúc: G[entity_type][entity_id][relation] = tuple(ids). Mỗi lần thêm edge đều ghi cả hai chiều (head→tail và tail→head), nên đồ thị vô hướng. Toy bên dưới coi mọi enrolment đã lọc là train.

6. Path pattern và bước kế tiếp

config/UPGPR/mooc.json: path_pattern; kg_env.py, actor_critic.py, train_transe_model.py

Agent RL xuất phát từ 1 user và đi tối đa max_path_len (=3 trong config) bước trên KG tới 1 course để giải thích đề xuất. Chọn user và pattern để xem path trên toy KG (chỉ liệt kê course user chưa enrol):

Các bước trước agent: train_transe_model học embedding 100 chiều cho node và relation trên KG này (embed_size 100, 30 epoch). train_agent dùng actor-critic (hidden 512,256; max_acts 250; gamma 0.99). PGPR/UPGPR chuyển bằng config (reward, use_pattern, max_path_len, topk), không đổi code.

Lưu ý / điểm có thể hỏi thầy

  • Đếm concept dùng raw, đếm user dùng sau lọc school. Hai ngưỡng khác dấu (> vs >=), có chủ ý không?
  • Concept không bị giới hạn theo course còn lại, nên vocab concept có thể chứa node mồ côi (degree 0 ngoài self-loop).
  • Split theo user ngẫu nhiên, không theo thời gian. Nếu dữ liệu có timestamp thì split theo thời gian sẽ sát thực tế hơn; MOOCCube raw 4 file này không có cột thời gian.
  • KG không dùng use_user_relations, use_entity_relations (đều false), nên không có quan hệ concept-concept (prerequisite) của MOOCCube gốc.
  • Mỗi course đúng 1 school (course_to_school[c] = s ghi đè). Nếu raw có course thuộc nhiều school, chỉ school cuối còn lại.
  • Pattern 4 trong mooc.json ghi bước cuối là item_concept sau node school, có vẻ lệch với item_school. Cần kiểm tra lại trong code agent trước khi kết luận.
  • sklearn split: sau lần chia đầu phải còn ít nhất 2 course cho validation+test. Nhờ min_user_count=10 nên không lỗi; hạ ngưỡng xuống dưới 6 sẽ lỗi (xem ghi chú mục 4).
